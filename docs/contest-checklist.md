1. 赛事 README 的必须文件表未列 `mcp-config.example.json`，完整活动规则明确列入至少应有的文件，因此按完整规则补齐。

3. MCP 接入示例使用 `YOUR_MCP_TOKEN` 文本占位；赛事材料要求环境变量占位符。参赛配置应按后者编写，并说明由具体运行脚本或客户端进行变量解析，不能假设所有客户端会自动展开。
4. MCP README 给出工具名和用途，没有完整输入 schema 或结果字段约定。正式执行应通过 MCP `tools/list` 获取当前 schema，不应把猜测参数、样例字段或解析成功视为真实调用成功。

## 「尝新预算」的能力边界与验收

以下是本项目已实现的查询链路，具体启用项以最终代码和 `MCP_INTEGRATION.md` 为准。

| 能力 | 官方工具 | 验收注意点 |
| --- | --- | --- |
| 当月活动线索 | `campaign-calendar` | 区分进行中、过去与未来活动；活动存在不等于所选门店在售，也不等于用户从未尝过。 |
| 门店选择 | `query-nearby-stores` | 用户提供地点后查询附近门店；真实门店标识来自工具结果。 |
| 当前可售菜单 | `query-meals` | 按已选门店查询；餐品标识、在售状态来自真实结果。 |
| 套餐组成和替换项 | `query-meal-detail` | 按实际餐品查询，不能虚构组合或默认全部可替换。 |
| 门店可用优惠券 | `query-store-coupons` | 仅在授权的用户账户和门店范围查询；账户数据不进入公开示例或分享内容。 |
| 核算价格 | `calculate-price` | 以实际商品组合和适用优惠计算；预算比较依据返回金额，不能把宣传价或菜单展示价当最终应付价。 |

「尝新」宜由用户表达的偏好或明确的活动信息定义，不能在未查询或未获得完整依据时声称某商品是该用户第一次吃。若以后使用历史订单辅助判断，`order-list` 的官方用途为近期到店/外送历史记录，不代表用户全部消费历史。

- [x] 真实查询失败、缺字段、餐品不可售、没有预算内组合时明确返回结果，不补造商品、优惠或价格。
