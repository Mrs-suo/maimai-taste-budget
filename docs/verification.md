### 发现并修复

1. 实时模式快捷预算只改输入、不更新结果：现在预算和热量在本次报价上立即筛选，验证切换 0/5 元和 700/500 千卡没有新增 API 请求。重新核价仍由主按钮明确触发，超过十分钟要求刷新报价。
2. 旧结果/旧套餐在查询失败或切换条件后可能残留：改变地标、门店、时段、套餐或替换项时清除下游状态，重查失败不保留旧推荐。
3. 手机查询反馈不明显：增加查询阶段提示、下一步滚动定位、错误聚焦、返回预算入口。输入框字号至少 16px，主要触摸按钮至少 44px。
4. 不可替换的固定主食仍出现在替换列表：现在只显示真正有多个可选项的轮次。
5. 重新核价时服务器排除了不喜欢项，清除偏好无法恢复：网页请求完整候选，本机过滤偏好，清除即可恢复；CLI 的显式 avoidCodes 能力保留。
6. 门店时间排序不连贯：预约选项去重后按时间排列。城市/地标支持 Enter 查询。

### 浏览器与失败路径

官方套餐、玉米杯、扭扭薯和肉骨鸡图片真实加载成功。模拟官方图片网络不可达时显示缺图说明，价格和预算筛选仍可用。模拟菜单 503 后错误被聚焦、旧数据清空、按钮恢复，随后真实菜单查询成功。无 JavaScript 未捕获异常。

320、375、390、768、1440 像素视口均无水平溢出。属于 Chromium 触屏/视口模拟，未声称完成实体 iPhone/Android 真机或 Safari 测试。

新增可重复执行的 `test/browser-ux.mjs`（使用脱敏 fixture、模拟 API 和图片失败，不需要真实凭证）。它验证实时筛选不重复请求、偏好恢复、不可替换项过滤、图片失败、旧状态清除、菜单重试及手机布局。需要已有 Playwright；可设置 `PLAYWRIGHT_MODULE` 为安装目录、`BROWSER_EXECUTABLE` 为现有浏览器绝对路径，然后 `node test/browser-ux.mjs`。未增加运行时 npm 依赖。
